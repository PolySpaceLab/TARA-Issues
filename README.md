## About TARA

**TARA (Toolkit for Astrodynamics Research and Application)** is a space mission design, analysis, and operations platform developed by **PolySpace Lab**.

TARA aims to make advanced astrodynamics and space mission engineering tools more accessible through an intuitive, interactive, web-based environment. It supports workflows for mission design, analysis, and operation. 

Our goal is to create a platform that serves students, researchers, and the space industry.

**Your feedback is essential to improving TARA.**

This public repository is dedicated to collecting, organizing, and tracking user feedback. Whether you encounter a software bug, identify an accessibility barrier, or have an idea for a new capability, we encourage you to share it here.

> **Note:** This repository is intended for issue tracking and community feedback. It does not contain TARA's application source code.

## What Can You Report?

We welcome feedback in three primary categories.

### 🐛 1. Report a Bug

Encountered something that does not work as expected?

Submit a bug report to help us identify, reproduce, and resolve software issues.

Examples include:

- Unexpected application behavior or error messages.
- Incorrect simulation results.
- User interface elements that do not function correctly.
- Performance problems, application freezes, or crashes.

**When reporting a bug, please provide:**

1. **A descriptive title:** Briefly summarize the problem.
2. **Description:** Explain what went wrong.
3. **Steps to reproduce:** Provide a step-by-step description of how to encounter the issue.
4. **Expected behavior:** Explain what you expected TARA to do.
5. **Actual behavior:** Describe what happened instead.
6. **Environment:** Specify your browser, operating system, and relevant application details.
7. **Supporting materials:** Include screenshots, error messages, or sample data, if available.

**[Submit a Bug Report](../../issues/new/choose)**

### ♿ 2. Request an Accessibility Feature

We want TARA to be usable by everyone, regardless of their abilities, experience, or preferred interaction methods.

If you experience an accessibility barrier or have an idea to make TARA more inclusive, please let us know.

Examples include:

- Improved keyboard navigation.
- Screen reader support and descriptive labels.
- Higher-contrast visualization options.
- Adjustable text sizes and interface scaling.
- Improved color accessibility for orbital plots.

**When submitting an accessibility request, please provide:**

1. **A descriptive title:** Identify the accessibility issue or requested improvement.
2. **Affected feature:** Indicate the part of TARA involved.
3. **Accessibility barrier:** Describe the difficulty encountered.
4. **Expected improvement:** Explain what would make the experience more accessible.
5. **Supporting information:** Include relevant screenshots, assistive technology details, or accessibility standards, if applicable.

**[Submit an Accessibility Request](../../issues/new/choose)**

### 💡 3. Request a New Feature

Have an idea that could improve TARA or expand its capabilities?

We welcome new feature suggestions from the TARA community.

Examples include:

- Additional perturbation and environmental models.
- Advanced mission planning and optimization tools.
- New orbital visualization and plotting features.
- Support for additional spacecraft and sensor models.
- Improved data import/export workflows.

**When requesting a feature, please provide:**

1. **A descriptive title:** Summarize your idea.
2. **Motivation:** Explain the need for the feature.
3. **Proposed functionality:** Describe what you would like TARA to support.
4. **Use case:** Explain how the feature would benefit your work or workflow.
5. **Examples or references:** Include supporting illustrations, publications, or references, if relevant.

**[Submit a Feature Request](../../issues/new/choose)**

## How to Submit an Issue

You can report an issue directly through the TARA web application or through this GitHub repository.

### Option A: Submit Through TARA

1. Open the **TARA**.
2. Click on the **Need Help*** button or navigate to the **Contact** page.
3. Find the **Inquiry Type** menu.
4. Select one of the following:
   - Report a Bug
   - Request Accessibility Feature
   - Request New Feature
5. Select the appropriate issue category.
6. Complete the issue form with as much information as possible.
7. Click **Submit** button.

### Option B: Submit Directly Through GitHub

1. Navigate to the **[Issues](../../issues)** tab of this repository.
2. Click **New issue**.
3. Select the appropriate issue template.
4. Provide a descriptive title and complete the requested information.
5. Review your submission for clarity and completeness.
6. Click **Submit new issue**.

> **GitHub account required:** You must be signed in to GitHub to submit an issue. If you do not have an account, you can create one at [github.com](https://github.com/signup).

Before creating an issue, please search existing issues to check whether the problem or feature request has already been reported.

If a similar issue exists, consider adding relevant details or a reaction instead of opening a duplicate.

## How to Track Your Issue

Once an issue has been submitted, it receives a unique GitHub issue number and a dedicated page where its progress can be followed.

### 1. Locate Your Issue

Visit the **[Issues](../../issues)** page to view submitted reports and feature requests.

You can search by keywords, issue number, or category.

### 2. Understand Issue Status

We use GitHub labels to help organize and communicate the status of reported issues.

| Label | Meaning |
|---|---|
| `bug` | A reported software defect or unexpected behavior. |
| `accessibility` | An accessibility-related issue or enhancement. |
| `enhancement` | A request for new functionality or improvement. |
| `needs-triage` | The issue is awaiting initial review. |
| `needs-information` | Additional information is required from the reporter. |
| `confirmed` | The issue has been reviewed and verified. |
| `planned` | The issue has been accepted for future development. |
| `in-progress` | Work on the issue is underway. |
| `blocked` | Progress depends on another task or unresolved problem. |
| `duplicate` | The issue has already been reported elsewhere. |

The TARA development team maintains these labels. Not all issues will necessarily receive every status label.

### 3. Follow Updates

To receive notifications:

1. Open the issue you want to follow.
2. Click **Subscribe** in the GitHub issue sidebar.
3. GitHub will notify you about new comments and relevant activity according to your notification settings.

You can also participate in discussions, provide additional information, or clarify your original request.

Closing an issue does not always mean that a software change has been released. Where applicable, the development team may provide additional information about the resolution.

## Guidelines for Submitting Feedback

To help us review and address issues efficiently, please follow these guidelines.

**Be specific.** Clearly describe the problem or requested functionality. Include enough technical information to understand the context.

**Submit one issue per problem.** Avoid combining unrelated bugs or feature requests into a single issue.

**Search before submitting.** Check existing issues to prevent duplicate reports.

**Provide reproducible steps.** For bug reports, include sufficient information to help the development team reproduce the behavior.

**Be constructive and respectful.** We encourage technical discussions, questions, and feedback that help improve the platform.

**Protect sensitive information.** Do not share passwords, API keys, access tokens, private mission data, personal information, or confidential research materials in public issues.
